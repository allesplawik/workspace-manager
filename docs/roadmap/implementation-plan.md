# Roadmapa WM 3.0

Zadania bez oznaczenia statusu są planowane i wymagają zatwierdzenia przed rozpoczęciem. [Macierz](feature-matrix.md) przypisuje wymagania do kodu i dowodów. Scenariusze są w [E2E](../testing/e2e-scenarios.md). Zakres i warunki STOP dla 3.0.0 określa [Release Contract](../release/3.0.0-release-contract.md), zatwierdzony przez właściciela. Ma pierwszeństwo w decyzjach wydaniowych.

WM-T01 jest zweryfikowane na macOS Intel oraz Ubuntu/Docker. Natywne Ubuntu i Apple Silicon były poza walidacją WM-T01. Zakres platform kandydujących do wsparcia określa Release Contract. [Raport fokusu](../testing/wm-t01-focus-regression.md). [WM-T02](../testing/wm-t02-ownership-reconciliation.md) wdraża wspólny kontrakt własności i blokad. WM-T02.1 domyka weryfikację i rejestrację historycznych niestandardowych socketów. WM-T03 domyka cykl życia worktree. Następne zadanie to WM-T04.

Multi-repository w MVP oznacza zarządzanie kilkoma niezależnymi repozytoriami w jednym workspace. Wspólne zadanie z koordynacją worktrees i sesji jest poza MVP. W 3.0.0 obowiązuje natywny picker Claude. Osobny katalog jest odłożony zgodnie z Release Contract.
